# 📚 1주차 미션 - 문자열 덧셈 계산기

## 🧠 유즈케이스 (Use Cases)
---

### UC-01 기본 구분자 합계 계산

**목적:** `,` 또는 `:`로 구분된 양의 정수들의 합을 계산한다.  
**사전조건:** 입력은 비어있지 않고, 구분자와 양의 정수로만 이뤄져야 한다.  
**사후조건:** 합계 정수를 출력한다.

**예시**

- `"1,2:3"` → `6`
- `"1,2,3"` → `6`
- `"1,2"` → `3`

---

### UC-02 커스텀 구분자 합계 계산

**목적:** 사용자 지정 단일 문자 구분자(`"//" + (문자) + "\n"`)로 합계를 계산한다.  
**사전조건:** 구분자는 모호성이 없어야 하며 형식이 정확해야 한다.  
**사후조건:** 합계 정수를 출력한다.

**예시**

- `"//;\n1;2;3"` → `6`
- `"//|\n2|3|4"` → `9`

---

### UC-03 빈 입력 처리

**목적:** 빈 입력(`null` 또는 `""`)은 합계 `0`으로 처리한다.  
**사후조건:** `0`을 출력한다.

**예시**

- `""` → `0`

---

### UC-04 형식/검증 오류 처리

**목적:** 사용자가 잘못된 값을 입력할 경우, 즉 계약 위반 시(빈 토큰, 음수·0, 숫자 외 문자, 선행 0, 커스텀 형식 위반 등)  
사용자에게 오류 메시지를 알리고 프로그램을 종료한다.  
**사후조건:** `IllegalArgumentException`에 해당하는 메시지를 출력하고 종료한다.

**오류 예시 입력**

- `"1,,2"`, `"1:"`, `","` - 토큰 무결성
- `"-1,2"`, `"0,1"`, `"1,a"`, `"01,2"` - 값 제약
- `"//\n1;2"`, `"//12\n1"`, `"//1\n1"` - 커스텀 구분자 형식

**오류 상세 정리**

| 입력          | 상황                                         | 예외 사유(규칙 위반) · 메시지 예시                                                            |
|-------------|--------------------------------------------|----------------------------------------------------------------------------------|
| `"1,,2"`    | 구분자 `,`가 연속으로 등장 → 중간에 **빈 토큰** 생성         | **비어 있는 토큰 금지** → `비어 있는 토큰은 허용되지 않습니다: index=1`                                 |
| `"1:"`      | 마지막에 구분자로 끝남 → **말단 빈 토큰** 생성              | **비어 있는 토큰 금지** → `비어 있는 토큰은 허용되지 않습니다: index=1`                                 |
| `","`       | 입력 전체가 구분자 → **양쪽 모두 빈 토큰**                | **비어 있는 토큰 금지** → `비어 있는 토큰은 허용되지 않습니다: index=0`                                 |
| `"-1,2"`    | 음수 값 포함                                    | **양의 정수만 허용** / **0·음수 금지** → `양의 정수만 허용됩니다: -1` *(또는)* `0 또는 음수는 허용되지 않습니다: -1` |
| `"0,1"`     | 0 포함                                       | **0 금지** → `0 또는 음수는 허용되지 않습니다: 0`                                               |
| `"1,a"`     | 숫자가 아닌 문자 `a` 포함                           | **비숫자 금지** → `양의 정수만 허용됩니다: a`                                                   |
| `"01,2"`    | `01`처럼 **선행 0** 포함                         | **선행 0 불허(정책 고정)** → `선행 0은 허용되지 않습니다: 01`                                       |
| `"//\n1;2"` | 커스텀 선언부 `"//" + (구분자) + "\n"`에서 **구분자 누락** | **커스텀 형식 위반** → `커스텀 구분자 형식이 올바르지 않습니다: //X\n...`                                |
| `"//12\n1"` | 커스텀 구분자가 **단일 문자 아님**(두 글자 `12`)           | **커스텀 구분자 길이 위반** → `커스텀 구분자는 단일 문자여야 합니다: 12`                                   |
| `"//1\n1"`  | 커스텀 구분자가 **숫자** (`'1'`)                    | **숫자 구분자 금지(혼동 방지 정책)** → `커스텀 구분자가 숫자일 수 없습니다: 1`                               |

---

### UC-05 정수 범위/합계 오버플로우

**목적:** 토큰 또는 합계가 `long` 범위를 초과하면 예외 처리한다.  
**사후조건:** 오류 메시지를 출력한 후 프로그램을 종료한다.

**예시**

- `"99999999999999999999,1"` → 토큰 파싱 실패(너무 큰 숫자 + 정상숫자)
- `"9223372036854775807,1"` → 합계 오버플로우(최대 long +1)

---

### UC-06 공백 처리

**목적:** 토큰 단위의 선행/후행 공백은 제거하여 계산한다.  
**사후조건:** 공백을 제거한 후 검증 및 계산을 수행한다.

**예시**

- `" 1 , 2 : 3 "` → `6`

---

## 📋 구현할 기능 목록

### A. I/O (애플리케이션 경계) — [공통]

- [ ] 시작 문구 출력: `덧셈할 문자열을 입력해 주세요.`
- [ ] 입력 읽기: `camp.nextstep.edu.missionutils.Console.readLine()` 사용ㄴ
- [ ] 정상 결과 출력: `결과 : {합계}`
- [ ] 예외 발생 시: **예외 메시지 그대로 출력 후 자연 종료** (*`System.exit()` 금지*)

---

### B. 기본 합계 계산 — UC-01

- [ ] 기본 구분자 지원: **쉼표 `,`**, **콜론 `:`**
- [ ] 구분자로 분리된 **양의 정수**들의 합을 반환
- [ ] 예시: `"1,2:3" → 6`, `"1,2,3" → 6`, `"1,2" → 3`

---

### C. 커스텀 구분자 — UC-02

- [ ] 형식 인식: `"//" + (단일 문자) + "\n" + 본문`
- [ ] **모호성 없는 구분자만 허용**(숫자 등 혼동 유발 문자 **금지** 정책)
- [ ] 커스텀 구분자로 토큰화 후 합계 계산
- [ ] 예시: `"//;\n1;2;3" → 6`, `"//|\n2|3|4" → 9`
- [ ] 형식 위반 시 **예외**(아래 UC-04 명세)

---

### D. 빈 입력 처리 — UC-03

- [ ] 입력이 `null` 또는 `""`이면 합계 **0** 반환
- [ ] 출력: `결과 : 0`

---

### E. 검증 정책 (Validation) — UC-04

#### E-1. 토큰 무결성

- [ ] **빈 토큰 금지**: 빈 토큰 발견 → 예외
    - 예: `"1,,2"`, `"1:"`, `","`
    - 메시지 예: `비어 있는 토큰은 허용되지 않습니다: index={i}`

#### E-2. 값 제약

- [ ] **양의 정수만 허용**: **음수/0/부호/문자 포함 → 예외**
    - 예: `"-1,2"`, `"0,1"`, `"1,a"`
    - 메시지 예: `양의 정수만 허용됩니다: {token}` 또는 `0 또는 음수는 허용되지 않습니다: {token}`
- [ ] **선행 0 불허**: `"01"` → 예외
    - 메시지 예: `선행 0은 허용되지 않습니다: {token}`

#### E-3. 커스텀 구분자 형식

- [ ] **구분자 누락 금지**: `"//\n..."` → 예외
    - 메시지 예: `커스텀 구분자 형식이 올바르지 않습니다: //X\n...`
- [ ] **단일 문자만 허용**: `"//12\n..."` → 예외
    - 메시지 예: `커스텀 구분자는 단일 문자여야 합니다: 12`
- [ ] **숫자 구분자 금지(정책)**: `"//1\n..."` → 예외
    - 메시지 예: `커스텀 구분자가 숫자일 수 없습니다: 1`

---

### F. 공백 처리 — UC-06

- [ ] 각 토큰에 `trim()` 적용 후 검증/해석
- [ ] 예시: `" 1 , 2 : 3 " → 6`

---

### G. 범위/오버플로우 — UC-05

- [ ] **파싱 범위 초과**: 각 토큰이 `long` 범위 외 → 예외
    - 예: `"99999999999999999999,1"`
    - 메시지 예: `정수 범위를 초과했습니다: token={token}`
- [ ] **합계 오버플로우 감지**: `Math.addExact` 사용, 발생 시 `IllegalArgumentException`으로 변환
    - 예: `"9223372036854775807,1"`
    - 메시지 예: `정수 범위를 초과했습니다: sum overflow`

---

### H. 내부 설계 원칙(검증)

- [ ] **Tell, Don’t Ask**: 외부에서 상태를 꺼내 검증하지 말고, 검증기는 `validate(tokens)`로 **명령**받는다.
- [ ] **캡슐화**: 검증/토큰화/정책 로직은 **내부에 감추고**, **메시지(인터페이스)** 만 노출.
- [ ] **메시지 우선**: **인터페이스(메시지) → 구현(메서드)** 순서로 설계.

## 🧾 문자열 덧셈 계산기 — RDD(책임-주도 설계) 관점 정리

### 1️⃣ 협력(대화) 시나리오 — 메시지 흐름

| **송신자**             | **수신자**                 | **메시지**                              | **설명**                                                  |
|---------------------|-------------------------|--------------------------------------|---------------------------------------------------------|
| 사용자                 | **View(InputView)**     | 입력 제공                                | 콘솔에서 문자열을 입력한다.                                         |
| Controller          | **Calculator**(도메인 파사드) | `sumOf(String input)`                | 입력 문자열의 합계를 계산하도록 **무엇을 할지** 요청한다.                      |
| **Calculator**      | **Expression**          | `parse(String input)`                | 입력을 계산 가능한 표현으로 변환하라는 요청 *(입력 해석 오케스트레이션 시작)*           |
| **Expression**      | **DelimiterPolicy**     | `resolve(String input)`              | 사용할 구분자 규칙을 결정하라는 요청 *(기본/커스텀 판별)*                      |
| **DelimiterPolicy** | **Expression**          | **return** `Delimiters`              | 결정된 구분자 집합을 **값 객체**로 반환                                |
| **Expression**      | **Tokenizer**           | `tokenize(String input, Delimiters)` | 구분자 규칙에 따라 문자열을 **토큰 리스트**로 분리 *(트리밍 포함)*               |
| **Tokenizer**       | **Delimiters**          | `toRegex()`                          | 구분자 집합을 토크나이저가 이해할 **정규식**으로 변환 요청                      |
| **Expression**      | **Validator**           | `validate(List<String> tokens)`      | 추출된 토큰이 불변식/정책을 위반하지 않는지 검증 *(빈 토큰, 음수/0, 비숫자, 선행 0 등)* |
| **Expression**      | **Numbers**             | `Numbers.from(List<String> tokens)`  | 유효한 토큰을 **숫자 컬렉션**으로 변환                                 |
| **Expression**      | **Calculator**          | **return** `Numbers`                 | 숫자 컬렉션을 반환                                              |
| **Calculator**      | **Numbers**             | `sum()`                              | 숫자 컬렉션의 **합계**를 계산 *(오버플로 감지)*                          |
| **Numbers**         | **Calculator**          | **return** `long`                    | 계산된 합계를 반환                                              |
| **Calculator**      | **Controller**          | **return** `long`                    | 최종 합계를 반환                                               |
| **Controller**      | **View(OutputView)**    | `printResult(long sum)`              | 출력 단으로 전달, **정상 결과** 출력                                 |

> 💡 협력은 요청–응답 메시지로 표현되며, 메시지가 **인터페이스를 결정**한다.  
> 각 객체는 자율적으로 내부 메서드를 선택하여 행동한다 (**캡슐화**).

### 2) 🧩 역할 · 책임 · 메시지 (Role–Responsibility–Message)

| **역할(Role)**        | **책임(Responsibility)**                  | **공개 메시지(Interface)**                               | **계층**     |
|---------------------|-----------------------------------------|-----------------------------------------------------|------------|
| **InputView**       | 사용자 입력 수집                               | `String readLine()`                                 | View       |
| **OutputView**      | 결과/오류 출력                                | `void printResult(long)`, `void printError(String)` | View       |
| **Controller**      | 흐름 제어 *(입력 → 도메인 호출 → 출력)*              | `void handle()`                                     | Controller |
| **Calculator**      | 도메인 파사드(합계 계산 진입점)                      | `long sumOf(String input)`                          | Domain     |
| **Expression**      | 입력 해석 오케스트레이션 *(정책 → 토큰화 → 검증 → 숫자)*    | `Numbers parse(String input)`                       | Domain     |
| **DelimiterPolicy** | 구분자 규칙 제공 *(기본/커스텀)*                    | `Delimiters resolve(String input)`                  | Domain     |
| **Tokenizer**       | 구분자 규칙으로 **토큰 분리/트리밍**                  | `List<String> tokenize(String, Delimiters)`         | Domain     |
| **Validator**       | 불변식 검증 *(빈 토큰, 음수/0, 비숫자, 선행 0, 형식 위반)* | `void validate(List<String>)`                       | Domain     |
| **Numbers**         | **불변** 숫자 컬렉션, 합산 *(오버플로 감지)*           | `long sum()`                                        | Domain     |
| **Delimiters**      | 구분자 값 객체 *(정규식 변환)*                     | `String toRegex()`                                  | Domain     |
